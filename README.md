# pii-scan

[![tests](https://github.com/basovdanil/pii-scan/actions/workflows/tests.yml/badge.svg)](https://github.com/basovdanil/pii-scan/actions/workflows/tests.yml)

[English](README.en.md) · **Русский**

Ищет персональные данные в CSV-выгрузке до того, как файл уйдёт наружу, и возвращает ненулевой
код — это годится как условие в конвейере.

```
python pii_scan.py выгрузка.csv
```

```
выгрузка.csv: 3 rows, 4 columns with findings, 8 matches
  email: 2 (email=2); examples: i***@example.com, p***@example.com
  phone: 3 (phone=3); examples: ***52, ***67, ***67
  passport: 2 (passport=2); examples: ***56, ***56
  note: 1 (snils=1); examples: ***64
```

Что находит: адреса почты, российские телефоны в обычных написаниях (`+7 900 123-45-67`,
`8 (495) 123-45-67`, `89001234567`), пары «серия и номер» паспорта, СНИЛС. В отчёте нет исходных
значений — только маска вида `i***@example.com` или `***52`, поэтому отчёт можно пересылать.

## Запуск

```
python pii_scan.py <файл.csv> [--json] [--delimiter ';']
```

- `--json` печатает объект отчёта: строки, колонки, находки по колонкам, итоги по типам;
- `--delimiter` для выгрузок Excel и 1С с `;`;
- UTF-8 с BOM и без; для windows-1251 кодировка задаётся в коде (один аргумент).

Коды возврата: `0` — ничего не найдено, `2` — неверные аргументы, `3` — файл не читается,
`4` — найдены персональные данные.

## Чем это не является

Это датчик дыма, а не средство комплаенса. Он ищет по форме, поэтому пропускает всё
неструктурированное (фамилия в свободном комментарии) и может отметить безобидное число, похожее
на телефон. Инструмент нужен, чтобы ловить очевидную утечку в выгрузке, а не чтобы подписывать
разрешение на передачу данных.

## Тесты

```
python -m unittest discover -s tests
```

15 тестов: каждый тип на фикстуре, маскирование, отсутствие исходных значений в отчёте, файл в
cp1251, разделитель `;`, пустой файл, все коды возврата, форма `--json`.

Python 3.8+, только стандартная библиотека.
